# Initial measured results

Run date: **2026-11-27**. Benchmark target: the current Go `skill-cli` alpha, a direct official-SDK native MCP peer, and a native progressive-discovery control. The reusable skill was generated, validated, and installed locally at `~/.codex/skills/skill-cli`; its distributable source is [skills/skill-cli](../skills/skill-cli/SKILL.md).

**The completed run measures retrieval and tokenized context components. No LLM-selection accuracy or billed model cost was measured:** the environment exposed no model API key, and the probed local model endpoints were unavailable. Those fields are explicitly `null` in [model-status.json](artifacts/model-status.json). The working [model runner](model_runner.py) is ready for a configured endpoint; fake-response unit tests are not presented as model results.

## Retrieval context relevance

The frozen catalog was evaluated with **40 labeled tasks**: 16 exact-name, 5 keyword, 8 paraphrase, 4 multi-operation, and 7 negative/abstention tasks. Gold positive tasks contain 37 required capability instances in total. Native and CLI discovery ran against the same local MCP replay; none of these retrieval trials depended on changing public-server results.

| Exposure/discovery strategy | Micro candidate precision | Positive micro recall | Mean visible token components |
| --- | ---: | ---: | ---: |
| Native eager: expose all 17 complete schemas | 5.44% | 100.00% | 1,900 |
| Native progressive: prescribed substring query | 48.33% | 78.38% | 390 |
| skill-cli: same prescribed query | 48.33% | 78.38% | 1,287 |
| skill-cli: full task text used as a literal substring | Undefined: no candidates | 0.00% | 1,150 |
| skill-cli: literal search, then list-all on no results | 5.44% | 100.00% | 2,399 |

**Candidate precision is relevance of the exposed context, not a model's selected-tool precision.** The eager arm includes all candidates by construction; its low relevance precision says nothing about whether a model can select the correct tool. Prescribed queries are analyst-supplied probes, not generated by a model. Therefore this table cannot rank agent accuracy or demonstrate that CLI reasoning beats native MCP reasoning.

The strongest controlled finding is **native progressive and skill-cli produced identical candidate IDs for every prescribed query**. Their precision/recall is the same because both use the same substring predicate. The CLI arm pays for its complete 879-token skill plus its shell definition/provider list; the native progressive arm uses a smaller purpose-built discovery router. That overhead is included rather than hidden.

On exact-name queries, recall was 100%; substring collisions kept precision below 100%. On all eight paraphrase probes, recall was 0%. The skill teaches shorter discriminating queries and list fallback, but the implementation does not provide semantic search. The full-task literal arm intentionally shows what happens when a substring search is treated as semantic retrieval. List-all recovers context recall at the cost of irrelevant candidates and more context.

## Token interpretation

The 17 complete native function schemas occupy **1,812 `o200k_base` tokens** before common instructions and the task. Including measured bootstrap, query, and discovery-result components, the CLI prescribed strategy used about **32.2% fewer visible components** than eager exposure in this small catalog. The broad fallback used about **26.3% more**. Neither percentage is a billable-token saving: model-specific tool framing, repeated conversation inputs, schema-describe followups, query generation, and final model output are not measured in this no-key run.

The native progressive control was smaller still. This supports progressive disclosure as the useful architectural mechanism; it does not establish an inherent token advantage for a CLI transport. A full model run may pay extra turns to refine queries and retrieve schemas, and should use provider-reported usage for the comparison.

Synthetic schema replication produced approximately 18,612 tokens for 170 tool definitions and 186,102 for 1,700. These are deliberately labeled synthetic scale examples, not additional live capabilities or quality measurements.

The full [retrieval artifact](artifacts/retrieval.json) records exact counts, per-task candidate sets, group metrics, package versions, and catalog/task fingerprints. Tokenizer: `tiktoken 0.12.0`, `o200k_base`. HTTP dependencies: `requests 2.32.5`, PyYAML 6.0.2.
